# Welo 前端接入说明

## 1. 接入范围

本文档面向 Welo 前端开发，按当前后端代码已经实现的行为编写。

当前后端地址由前端环境变量提供，不要把地址写死在业务组件中：

```ts
const API_BASE_URL = import.meta.env.VITE_API_BASE_URL ?? "";
```

开发环境建议：

```text
VITE_API_BASE_URL=http://localhost:8787
```

接口统一前缀：

```text
/api/v1
```

健康检查接口不带版本前缀：

```text
GET /health
```

## 2. 请求基础封装

推荐所有请求都经过一个统一的 `apiFetch`，统一处理认证、JSON、错误和 `requestId`。

```ts
const API_BASE_URL = import.meta.env.VITE_API_BASE_URL ?? "";

export class ApiRequestError extends Error {
  code: string;
  status: number;
  details: Array<{ field?: string; reason: string }>;

  constructor(
    message: string,
    options: {
      code: string;
      status: number;
      details?: Array<{ field?: string; reason: string }>;
    },
  ) {
    super(message);
    this.name = "ApiRequestError";
    this.code = options.code;
    this.status = options.status;
    this.details = options.details ?? [];
  }
}

export async function apiFetch<T>(
  path: string,
  options: RequestInit = {},
): Promise<T> {
  const headers = new Headers(options.headers);
  headers.set("Accept", "application/json");

  if (options.body && !headers.has("Content-Type")) {
    headers.set("Content-Type", "application/json");
  }

  const response = await fetch(`${API_BASE_URL}${path}`, {
    ...options,
    headers,
    credentials: "include",
  });

  const payload = await response.json().catch(() => null);

  if (!response.ok) {
    throw new ApiRequestError(
      payload?.error?.message ?? "请求失败",
      {
        code: payload?.error?.code ?? "UNKNOWN_ERROR",
        status: response.status,
        details: payload?.error?.details ?? [],
      },
    );
  }

  return payload as T;
}
```

如果前端不使用 Cookie，也可以保存登录接口返回的 Bearer Token，并在请求中增加：

```ts
headers.set("Authorization", `Bearer ${token}`);
```

浏览器页面优先使用 HttpOnly Cookie，不建议前端自行保存会话 token。

## 3. 通用响应类型

```ts
export interface Pagination {
  page: number;
  pageSize: number;
  total: number;
  totalPages: number;
}

export interface ApiMeta {
  requestId: string;
  pagination: Pagination | null;
}

export interface ApiEnvelope<T> {
  data: T;
  meta: ApiMeta;
}

export interface ApiErrorPayload {
  error: {
    code: string;
    message: string;
    details?: Array<{
      field?: string;
      reason: string;
    }>;
  };
  meta: {
    requestId: string;
  };
}
```

业务数据在 `response.data`，分页信息在 `response.meta.pagination`。

## 4. 用户和认证

### 4.1 注册

```http
POST /api/v1/auth/register
Content-Type: application/json
```

请求：

```json
{
  "username": "linyizhou",
  "email": "linyi@example.com",
  "password": "password123",
  "passwordConfirmation": "password123"
}
```

成功状态码：`201`

返回：

```json
{
  "data": {
    "user": {
      "id": "1",
      "username": "linyizhou",
      "email": "linyi@example.com",
      "systemRole": "member",
      "createdAt": "2026-09-07T08:30:00.000Z"
    },
    "onboardingRequired": true
  }
}
```

注册成功后后端会直接写入会话 Cookie，前端可以直接进入初始化流程。

### 4.2 登录

```http
POST /api/v1/auth/login
Content-Type: application/json
```

请求：

```json
{
  "account": "linyi@example.com",
  "password": "password123"
}
```

`account` 可以填写邮箱或用户名。

可能的结果：

| 状态码 | 错误码 | 前端处理 |
| --- | --- | --- |
| 200 | - | 保存用户状态并进入应用 |
| 401 | `INVALID_CREDENTIALS` | 提示账号或密码错误 |
| 423 | `ACCOUNT_LOCKED` | 提示账号暂时锁定 |

### 4.3 当前用户

```http
GET /api/v1/auth/me
```

返回当前用户和当前可访问团队：

```ts
interface AuthUser {
  id: string;
  username: string;
  email: string;
  systemRole: "super_admin" | "member";
  createdAt: string;
}

interface TeamSummary {
  id: string;
  name: string;
  description: string | null;
  status: "active" | "archived";
  createdAt: string;
  updatedAt: string;
}

interface MeData {
  user: AuthUser;
  teams: TeamSummary[];
}
```

应用启动时建议先调用该接口：

1. 请求成功：恢复登录状态；
2. 返回 `401`：清理前端登录状态并跳转登录页；
3. 根据 `user.systemRole` 决定是否显示超管入口；
4. 根据 `teams` 初始化当前团队。

### 4.4 退出

```http
POST /api/v1/auth/logout
```

成功后清理前端内存中的用户状态，并跳转登录页。

### 4.5 更新个人资料

```http
PATCH /api/v1/users/me
Content-Type: application/json
```

请求至少传一个字段：

```json
{
  "username": "new-name",
  "email": "new@example.com"
}
```

当前接口支持修改用户名和邮箱。语言字段虽然在设计文档中预留，但当前后端尚未保存该字段，前端暂不提交 `language`。

## 5. 团队接口

### 5.1 查询团队

```http
GET /api/v1/teams
```

超级管理员返回全部团队，普通成员返回自己加入的团队。

### 5.2 团队详情

```http
GET /api/v1/teams/{teamId}
```

普通成员访问不属于自己的团队时，后端返回 `404`，前端按资源不存在处理，不要单独暴露“无权访问”文案。

### 5.3 创建团队

仅超级管理员：

```http
POST /api/v1/teams
```

请求：

```json
{
  "name": "产品研发团队",
  "description": "负责 Welo 产品研发"
}
```

### 5.4 更新或归档团队

仅超级管理员：

```http
PATCH /api/v1/teams/{teamId}
```

请求示例：

```json
{
  "name": "新的团队名称",
  "description": "新的描述",
  "status": "archived"
}
```

归档后团队只读，前端应禁用新增和编辑入口。

### 5.5 团队成员

仅超级管理员：

```http
GET    /api/v1/teams/{teamId}/members
POST   /api/v1/teams/{teamId}/members
DELETE /api/v1/teams/{teamId}/members/{userId}
```

添加成员：

```json
{
  "userId": "2"
}
```

移除成员时，如果该用户仍负责任务，后端返回：

```text
409 MEMBER_HAS_ASSIGNMENTS
```

前端应提示管理员先转移或处理任务负责人。

## 6. 小组接口

```http
GET    /api/v1/teams/{teamId}/groups
POST   /api/v1/teams/{teamId}/groups
PATCH  /api/v1/teams/{teamId}/groups/{groupId}
GET    /api/v1/teams/{teamId}/groups/{groupId}/members
POST   /api/v1/teams/{teamId}/groups/{groupId}/members
DELETE /api/v1/teams/{teamId}/groups/{groupId}/members/{userId}
```

小组创建：

```json
{
  "name": "设计组",
  "description": "负责产品和视觉设计"
}
```

小组更新：

```json
{
  "name": "设计与体验组",
  "status": "disabled"
}
```

停用小组后：

- 历史任务仍保留；
- 小组仍可被查询；
- 不能创建新任务；
- 前端应保留历史任务查看能力，但禁用新任务创建时的该小组选项。

添加小组成员前，用户必须已经加入团队，否则返回 `409 CONFLICT`。

小组成员查询返回 `{ id, username }` 引用列表。超级管理员可查询任意小组；普通成员只能查询自己所属的小组，否则返回 `404 NOT_FOUND`。

## 7. 项目接口

### 7.1 项目列表

```http
GET /api/v1/teams/{teamId}/projects
```

支持查询参数：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `page` | number | 1 | 页码 |
| `pageSize` | number | 20 | 每页数量，最大 100 |
| `keyword` | string | - | 搜索项目名称和描述 |
| `status` | string | - | `active` 或 `archived` |

示例：

```text
/api/v1/teams/1/projects?page=1&pageSize=20&status=active&keyword=官网
```

### 7.2 创建项目

普通成员可以在自己所属团队创建项目：

```http
POST /api/v1/teams/{teamId}/projects
```

请求：

```json
{
  "name": "官网改版",
  "description": "完成官网首页和内容页面改版"
}
```

### 7.3 项目详情

```http
GET /api/v1/teams/{teamId}/projects/{projectId}
```

返回字段包括：

- `id`
- `teamId`
- `name`
- `description`
- `status`
- `taskCount`
- `createdBy`
- `createdAt`
- `updatedAt`

### 7.4 更新和删除项目

仅超级管理员：

```http
PATCH  /api/v1/teams/{teamId}/projects/{projectId}
DELETE /api/v1/teams/{teamId}/projects/{projectId}?confirmName=官网改版
```

删除项目是软删除。删除后前端应从项目列表移除，不需要立即删除本地任务缓存以外的历史数据。

## 8. 任务接口

### 8.1 任务类型

```ts
type TaskStatus = "todo" | "in_progress" | "done";
type TaskPriority = "low" | "medium" | "high" | "urgent";

interface Task {
  id: string;
  projectId: string;
  group: {
    id: string;
    name: string;
    status: "active" | "disabled";
    teamId: string;
    description: string | null;
    memberCount: number;
  };
  title: string;
  detail: string | null;
  assignee: {
    id: string;
    username: string;
  };
  startDate: string | null;
  endDate: string;
  renderStartDate: string;
  isVirtualStart: boolean;
  status: TaskStatus;
  priority: TaskPriority;
  completedAt: string | null;
  createdBy: {
    id: string;
    username: string;
  };
  createdAt: string;
  updatedAt: string;
}
```

时间格式：

- 任务起止时间：`YYYY-MM-DDTHH:mm`，分钟只能是 `00` 或 `30`，例如 `2026-09-10T09:30`；
- 时间戳：ISO 8601 UTC，例如 `2026-09-07T08:30:00.000Z`。

### 8.2 任务列表

```http
GET /api/v1/teams/{teamId}/projects/{projectId}/tasks
```

支持查询参数：

| 参数 | 说明 |
| --- | --- |
| `page` | 页码 |
| `pageSize` | 每页数量，最大 100 |
| `groupId` | 按小组筛选 |
| `assigneeId` | 按负责人筛选 |
| `status` | `todo`、`in_progress`、`done` |
| `priority` | `low`、`medium`、`high`、`urgent` |
| `keyword` | 搜索标题和详情 |
| `sortBy` | `endDate`、`createdAt`、`priority` |
| `sortOrder` | `asc` 或 `desc` |

示例：

```text
/api/v1/teams/1/projects/2/tasks?page=1&pageSize=20&status=in_progress&sortBy=endDate&sortOrder=asc
```

普通成员拿到的是自己所属小组任务的并集，不需要前端自行做小组过滤。前端也不能根据用户提交的角色字段自行放宽数据。

### 8.3 创建任务

```http
POST /api/v1/teams/{teamId}/projects/{projectId}/tasks
Content-Type: application/json
```

请求：

```json
{
  "title": "完成首页视觉稿",
  "detail": "补齐桌面端和移动端首页视觉稿",
  "groupId": "3",
  "assigneeId": "5",
  "startDate": "2026-09-10T09:30",
  "endDate": "2026-09-15T18:00",
  "status": "todo",
  "priority": "high"
}
```

必填字段：

- `title`
- `groupId`
- `assigneeId`
- `endDate`

后端会校验：

- 项目属于路径中的团队；
- 小组属于该团队；
- 小组处于 `active`；
- 普通成员属于该团队和任务小组；
- 负责人属于该小组；
- 开始时间不晚于结束时间；
- 起止时间按 30 分钟对齐。

### 8.4 查询任务详情

```http
GET /api/v1/teams/{teamId}/projects/{projectId}/tasks/{taskId}
```

### 8.5 修改任务

```http
PATCH /api/v1/teams/{teamId}/projects/{projectId}/tasks/{taskId}
```

请求可以只提交需要修改的字段：

```json
{
  "status": "done",
  "priority": "medium",
  "expectedUpdatedAt": "2026-09-07T08:30:00.000Z"
}
```

如果传 `expectedUpdatedAt`，后端会执行乐观锁校验。更新失败时返回：

```text
409 VERSION_CONFLICT
```

前端处理建议：

1. 保留用户刚才的编辑意图；
2. 重新请求任务详情；
3. 提示任务已经被其他人更新；
4. 让用户确认后再次提交。

任务状态变化规则：

- 改为 `done`：后端自动写入 `completedAt`；
- 从 `done` 改回其他状态：后端清空 `completedAt`。

### 8.6 删除任务

仅超级管理员：

```http
DELETE /api/v1/teams/{teamId}/projects/{projectId}/tasks/{taskId}
```

删除为软删除。

## 9. 甘特图接入

### 9.1 查询甘特图

```http
GET /api/v1/teams/{teamId}/projects/{projectId}/gantt?granularity=week
```

`granularity` 支持：

- `day`
- `week`
- `month`

返回：

```ts
interface GanttData {
  project: Project;
  range: {
    startDate: string;
    endDate: string;
    granularity: "day" | "week" | "month";
  };
  tasks: Task[];
}
```

如果任务的 `startDate` 为 `null`：

- `renderStartDate` 使用 `endDate`；
- `isVirtualStart` 为 `true`；
- 前端可以用虚线或单日条形展示；
- 不要把虚拟开始时间自动写回后端。

### 9.2 拖拽保存排期

```http
PATCH /api/v1/teams/{teamId}/projects/{projectId}/tasks/{taskId}/schedule
Content-Type: application/json
```

请求：

```json
{
  "startDate": "2026-09-11T10:00",
  "endDate": "2026-09-16T17:30",
  "expectedUpdatedAt": "2026-09-07T08:30:00.000Z"
}
```

`endDate` 和 `expectedUpdatedAt` 必填，`startDate` 可以为 `null`。

推荐交互流程：

1. 拖拽前记录任务原始日期；
2. 拖拽过程中只更新前端临时状态；
3. 拖拽结束后提交接口；
4. 成功：使用返回的最新任务覆盖本地任务；
5. `409 VERSION_CONFLICT`：回滚临时位置并重新拉取任务；
6. 其他错误：回滚临时位置并显示错误提示。

## 12. 前端路由接入顺序

建议按以下顺序开发和联调：

1. 登录页：登录、注册、退出；
2. 应用启动：`GET /auth/me` 恢复用户和团队；
3. 团队切换：`GET /teams`；
4. 工作台：`GET /teams/{teamId}/dashboard`；
5. 项目列表和项目创建；
6. 项目详情和任务列表；
7. 任务创建、编辑和状态切换；
8. 甘特图读取和拖拽保存；
9. 小组与成员管理；
10. 超级管理员后台。

## 13. 前端错误处理建议

建议封装统一错误处理：

```ts
function handleApiError(error: unknown) {
  if (!(error instanceof ApiRequestError)) {
    return "网络异常，请稍后重试";
  }

  switch (error.code) {
    case "UNAUTHENTICATED":
      return "登录状态已失效，请重新登录";
    case "FORBIDDEN":
      return "你没有执行此操作的权限";
    case "NOT_FOUND":
      return "内容不存在或你没有查看权限";
    case "VERSION_CONFLICT":
      return "内容已被其他人更新，请刷新后重试";
    case "MEMBER_HAS_ASSIGNMENTS":
      return "该成员仍负责任务，暂时不能移除";
    case "ACCOUNT_LOCKED":
      return "账号已暂时锁定，请稍后再试";
    case "VALIDATION_ERROR":
      return error.details[0]?.reason ?? error.message;
    default:
      return error.message;
  }
}
```

前端不应把服务端 `404` 细分为“资源不存在”和“无权限”，因为后端会故意统一返回 `404`，避免暴露其他团队或小组的数据存在性。

## 14. 当前接入限制

以下能力目前没有后端接口，前端暂不要实现真实提交逻辑：

- 密码找回；
- 修改密码；
- 评论；
- 附件；
- 任务依赖；
- 通知；
- 任务操作历史；
- 成员视图；
- 登录和写接口限流状态展示；
- CSRF Token 流程。

完整接口定义可参考仓库中的 [api-docs.yaml](./api-docs.yaml)，但如果 OpenAPI 文档与当前代码行为不一致，应以当前后端实现和本文档为准，并在联调时及时同步接口文档。
