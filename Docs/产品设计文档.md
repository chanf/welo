## 1. 产品概述

### 1.1 产品定位

一款面向多团队共用、以「小组」为最小权限单元的任务管理系统。系统以项目承载协作，以任务驱动执行，通过甘特图直观呈现与调整任务排期，适用于需要跨小组协同、但又要求组间数据隔离的研发、设计、运营等团队。

### 1.2 背景与问题

现有轻量 Todo 工具普遍存在以下问题：

1. 任务信息过于单薄，缺少负责人、起止时间、详细说明等完整字段，无法支撑正式协作；
2. 缺乏组织架构与权限体系，多团队共用时数据互相可见，存在泄露与干扰；
3. 缺少项目维度，任务散落在个人清单中，无法按项目沉淀与复盘；
4. 排期能力弱，无法直观查看时间分布，调整时间需要逐条编辑。

### 1.3 目标用户

| 用户角色 | 典型场景 |
| --- | --- |
| 超级管理员 | 管理全部人员、团队、项目和任务，负责人员的团队与小组分配 |
| 普通人员 | 在自己所属团队内创建项目、创建任务、修改任务详情并协作执行 |

### 1.4 核心设计原则

1. **组内可见**：默认情况下，成员只能看到自己所属小组的任务；
2. **一人多组**：用户可同时属于多个小组，看到的是所有所属小组任务的并集；
3. **项目先行**：任务必须挂在项目下，先建项目、再建任务；
4. **任务完整**：任务包含标题、详细内容、负责人、起止时间，字段完整可追踪；
5. **排期可拖**：甘特图支持直接拖拽调整开始/结束时间，所见即所得。

### 1.5 名词解释

| 名词 | 解释 |
| --- | --- |
| 团队（Team） | 顶层组织单位，多个团队共用一套系统，团队之间数据完全隔离 |
| 小组（Group） | 团队内的执行单元，任务可见性的最小隔离单位 |
| 项目（Project） | 团队内的工作容器，任务必须归属于某个项目 |
| 任务（Task） | 项目内的具体工作项，含标题、详细内容、负责人、起止时间等字段 |
| 甘特图（Gantt） | 以时间轴 + 条形图展示任务起止时间的视图，支持拖拽调整 |

## 2. 角色与权限体系

### 2.1 角色定义

| 角色 | 说明 | 来源 |
| --- | --- | --- |
| 超级管理员（Super Admin） | 平台级角色，拥有完整的人员、团队、项目、任务和系统管理权限，可访问所有数据 | 由系统初始化或已有超管授予 |
| 普通人员（Member） | 业务协作角色，由超管分配到一个或多个团队；在所属团队内拥有统一的项目与任务协作权限 | 注册后默认为普通人员，由超管分配团队 |

说明：系统不设置团队管理员、项目管理员或小组组长等中间角色。小组只用于划分任务可见范围，不用于区分操作权限。

### 2.2 权限矩阵

| 操作 | 超级管理员 | 普通人员 |
| --- | --- | --- |
| 查看与管理全部用户 | 可 | 不可 |
| 授予 / 撤销超级管理员 | 可 | 不可 |
| 创建、编辑、归档、删除团队 | 可 | 不可 |
| 将人员加入或移出团队 | 可 | 不可 |
| 创建 / 编辑 / 停用小组 | 可 | 不可 |
| 分配小组成员（可属多组） | 可 | 不可 |
| 查看全部团队、项目和任务 | 可，不受团队和小组限制 | 仅所属团队，任务再按所属小组过滤 |
| 创建项目 | 任意团队均可 | 可在所属团队创建 |
| 编辑 / 归档 / 删除项目 | 任意项目均可 | 不可 |
| 创建任务 | 任意项目均可 | 可在所属团队项目创建 |
| 修改任务详情与状态 | 任意任务均可 | 可修改自己可见的任务 |
| 删除任务 | 可 | 不可 |
| 甘特图拖拽调整时间 | 可 | 可调整自己可见的任务 |

### 2.3 数据可见性规则（核心）

以下规则为整个产品权限设计的基石，所有列表、详情、甘特图、统计接口必须遵循：

1. 任务可见范围 = 用户在当前团队内所属全部小组的任务并集；
2. 用户 A 只属于「前端组」，则 A 只能看到归属于前端组的任务，看不到「设计组」的任务；
3. 用户 B 同时属于「前端组」和「设计组」，则 B 能看到两个组任务的并集，并可通过「小组」筛选器按组过滤；
4. 项目的基本信息（名称、描述、状态）对团队内成员可见，但项目内的任务列表、任务详情、甘特图数据一律按上述小组规则过滤；
5. 超级管理员不受团队与小组可见性限制，可以查看和管理全部任务；普通人员严格按团队成员关系和小组成员关系过滤；
6. 任务负责人必须属于任务所归属的小组，保证「可见性」与「可执行性」一致；
7. 所有数据接口在服务端做可见性校验，前端过滤仅作为展示优化，不作为安全手段。

示例：

某团队下有两个小组：

- 前端组：张三、李四
- 设计组：李四、王五

项目「官网改版」中的任务：

- 「首页开发」→ 前端组，负责人张三
- 「视觉稿设计」→ 设计组，负责人王五

可见性结果：

| 用户 | 所属小组 | 可见任务 |
| --- | --- | --- |
| 张三 | 前端组 | 首页开发 |
| 李四 | 前端组、设计组 | 首页开发、视觉稿设计 |
| 王五 | 设计组 | 视觉稿设计 |

## 3. 功能需求

### 3.1 用户系统

#### 3.1.1 注册

注册不做邮箱验证，填写以下信息并简单校验通过后即完成注册：

| 字段 | 必填 | 校验规则 |
| --- | --- | --- |
| 用户名 | 是 | 2-32 个字符，支持中英文、数字、下划线，系统内唯一 |
| 邮箱 | 是 | 符合邮箱格式，系统内唯一，不区分大小写 |
| 密码 | 是 | 至少 8 位，不能与用户名相同 |
| 确认密码 | 是 | 必须与密码一致 |

交互规则：

1. 前端实时校验格式与两次密码一致性，错误在对应字段下方提示；
2. 提交后服务端重复校验（唯一性以后端为准）；
3. 注册成功后自动登录并进入引导页（创建团队或加入团队）；
4. 注册过程不发送验证邮件、不需要管理员审核。

#### 3.1.2 登录

| 字段 | 必填 | 校验规则 |
| --- | --- | --- |
| 账号 | 是 | 用户名或邮箱 |
| 密码 | 是 | 与账号对应的密码 |

规则：

1. 登录时必须验证密码，密码错误统一提示「用户名或密码错误」，不透露账号是否存在；
2. 密码以哈希存储（bcrypt 或 argon2），任何场景不得明文保存或回显；
3. 登录成功后创建会话（Token / Session），支持退出登录；
4. 连续 5 次失败后账号锁定 10 分钟（V1 实现，提示剩余等待时间）。

#### 3.1.3 账号安全（V1 最小集）

1. 密码单向哈希加盐存储；
2. 所有需要身份的接口校验会话有效性；
3. 越权访问（如直接请求不可见任务详情）返回 404，避免探测。

### 3.2 团队与小组管理

#### 3.2.1 团队

1. 仅超级管理员可创建、编辑、归档和删除团队；
2. 团队字段：名称（必填、团队内唯一）、描述（选填）；
3. 用户只能由超级管理员分配到一个或多个团队，团队之间数据完全隔离，顶部可切换当前团队；
4. 团队可被归档，归档后只读，不可新建项目与任务。

#### 3.2.2 小组

1. 仅超级管理员可创建、编辑、停用小组；
2. 小组字段：名称（必填、团队内唯一）、描述（选填）、状态（启用/停用）；
3. 停用小组后，该组历史任务保留并仍按可见性规则展示，但不能在该组下创建新任务；
4. 删除小组前必须先处理该组下所有任务（迁移到其他小组），否则不允许删除。

#### 3.2.3 成员管理

1. 超级管理员通过用户名或邮箱将已注册用户加入团队；
2. 一个成员可同时被分配到多个小组，系统不限制数量；
3. 成员可被移出某个小组，也可移出团队；移出后立即失去对应可见性；
4. 移出小组不影响其历史任务记录，历史任务中保留成员名称展示。

### 3.3 项目管理

#### 3.3.1 项目创建

1. 超级管理员可在任意团队创建项目；普通人员可在自己所属团队创建项目；
2. 项目创建人仅作为审计字段，不产生额外角色或专属权限；
3. 项目字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 项目名称 | 是 | 2-64 个字符，团队内唯一 |
| 项目描述 | 否 | 最多 2000 字，支持换行 |
| 所属团队 | 是 | 超管可选择任意团队；普通人员只能选择自己所属团队 |

#### 3.3.2 项目生命周期

状态：进行中 → 已归档。

1. 进行中：可正常创建、编辑任务；
2. 已归档：项目与任务全部只读，甘特图可查看不可拖拽；
3. 仅超级管理员可归档项目；归档可撤销（V1.1）；
4. 仅超级管理员可删除项目，需输入项目名二次确认；删除为软删除，任务保留 30 天可恢复。

#### 3.3.3 项目详情页结构

项目详情页是核心工作界面，包含三个页签：

1. 任务列表：默认视图，支持筛选与排序；
2. 甘特图：按时间轴展示任务，支持拖拽调整；
3. 成员视图：按负责人聚合任务（V1.1 提供）。

页签上方提供「小组筛选」下拉框（默认：全部可见小组），筛选结果同时作用于任务列表与甘特图。

### 3.4 任务系统

#### 3.4.1 任务字段

| 字段 | 必填 | 类型 / 格式 | 说明 |
| --- | --- | --- | --- |
| 标题 | 是 | 文本，1-200 字符 | 任务的一句话概述 |
| 详细内容 | 否 | 长文本，最多 10000 字符 | 支持换行；V1 纯文本，V1.1 支持 Markdown 预览 |
| 所属小组 | 是 | 选择器 | 决定任务可见性，默认记忆上次选择 |
| 负责人 | 是 | 选择器 | 必须属于所选小组成员列表 |
| 开始时间 | 否 | 本地时间（YYYY-MM-DDTHH:mm） | 分钟按 00 / 30 对齐；不填时甘特图按结束时间当天渲染 |
| 结束时间 | 是 | 本地时间（YYYY-MM-DDTHH:mm） | 分钟按 00 / 30 对齐，不能早于开始时间 |
| 状态 | 是 | 枚举 | 待办 / 进行中 / 已完成，默认待办 |
| 优先级 | 是 | 枚举 | 低 / 中 / 高 / 紧急，默认中 |

系统自动记录：创建人、创建时间、最后修改人、最后修改时间。

#### 3.4.2 任务校验规则

1. 标题、负责人、结束时间为必填，缺失时禁用提交并逐项提示；
2. 负责人下拉列表仅展示所选小组成员；切换小组后负责人清空重选；
3. 若填写了开始时间，开始时间不得晚于结束时间；
4. 起止时间必须按 30 分钟对齐；
5. 已归档项目下禁止任何任务写操作。

#### 3.4.3 任务状态流转

状态流转：待办 → 进行中 → 已完成。

1. 允许回退（如已完成改回进行中），回退需填写原因（V1.1）；
2. 负责人可更新自己任务的状态；
3. 状态变更为「已完成」时记录完成时间。

#### 3.4.4 任务列表视图

1. 列：标题、负责人、所属小组、开始时间、结束时间、状态、优先级；
2. 筛选：小组、负责人、状态、优先级、时间范围；
3. 排序：默认按结束时间升序，可按创建时间、优先级排序；
4. 行点击进入任务详情，详情页含全部字段与编辑历史（V1.1 提供历史）；
5. 列表数据严格按可见性规则过滤。

### 3.5 甘特图

#### 3.5.1 入口与布局

1. 入口：项目详情页「甘特图」页签；
2. 布局：左侧为任务信息栏（标题、负责人、起止时间），右侧为时间轴条形图区；
3. 时间粒度：小时 / 半天 / 天三档切换，默认按天；
4. 时间轴自动缩放到当前项目任务的最早开始（或最早结束）至最晚结束时间，前后各留 3 天空白；
5. 每个任务渲染为一个条形，条形长度代表起止时间跨度，颜色按状态区分（待办灰、进行中蓝、已完成绿）。

#### 3.5.2 无开始时间的渲染规则

1. 开始时间为空的任务，按「结束时间」渲染为当前颗粒度下的一个单元格条形，并以虚线边框标识；
2. 该任务不支持拖拽自动写入开始时间，列表与接口继续返回空开始时间；
3. 列表视图与导出数据中开始时间仍显示为空，不因渲染规则产生假数据。

#### 3.5.3 拖拽交互

| 交互 | 手势 | 结果 |
| --- | --- | --- |
| 整体移动 | 按住条形中部拖动 | 开始与结束时间同时平移，保持时长不变 |
| 调整开始时间 | 按住条形左边缘拖动 | 仅修改开始时间，结束时间不变 |
| 调整结束时间 | 按住条形右边缘拖动 | 仅修改结束时间，开始时间不变 |

拖拽规则：

1. 拖拽按天平移并保留任务原有的 00 / 30 分钟时刻，手动编辑可精确到 30 分钟；
2. 拖拽过程中实时显示时间预览气泡（如 09-10 09:30 ~ 09-18 18:00）；
3. 拖拽结束时间不得早于开始时间，拖拽开始时间不得晚于结束时间，越界时自动贴合并提示；
4. 松手后采用乐观保存：界面先更新，后台保存；保存失败时回滚原时间并 toast 提示「保存失败，请重试」；
5. 保存成功后，左侧任务信息栏的起止时间同步刷新；
6. 拖拽权限与任务编辑权限一致：超管可调整全部任务，普通人员可调整自己可见的任务。

#### 3.5.4 辅助能力

1. 悬停条形显示任务摘要卡片：标题、负责人、起止时间、状态；
2. 今日线：时间轴上高亮当天；
3. 甘特图数据与任务列表共享筛选条件（小组、负责人、状态等）；
4. 任务之间的依赖连线（完成-开始）放入 V2。

## 4. 页面结构与关键流程

### 4.1 页面清单

| 页面 | 路由建议 | 主要内容 |
| --- | --- | --- |
| 注册页 | /register | 用户名、邮箱、密码、确认密码 |
| 登录页 | /login | 账号、密码 |
| 引导页 | /onboarding | 创建团队 / 加入团队 |
| 工作台 | /workspace | 当前团队的项目列表、快捷入口 |
| 项目详情 | /projects/:id | 任务列表、甘特图、成员视图页签 |
| 任务详情 | /projects/:id/tasks/:taskId | 任务完整字段、编辑、状态操作 |
| 团队管理 | /team | 团队设置、小组管理、成员管理（仅管理员） |
| 个人设置 | /settings | 基本信息、退出登录、修改密码（V1.1） |

### 4.2 核心流程

#### 流程一：从注册到可协作

1. 用户填写用户名、邮箱、两次密码完成注册；
2. 自动登录进入引导页；
3. 等待超级管理员将其分配到团队和小组；
4. 进入所属团队；
5. 创建项目；
6. 在项目内创建任务，选择所属小组与负责人。

#### 流程二：多组用户的日常使用

1. 李四登录后进入「官网改版」项目；
2. 系统按其所属「前端组 + 设计组」返回任务并集；
3. 李四可通过小组筛选器只看某一组；
4. 李四更新自己负责任务的状态为「已完成」。

#### 流程三：甘特图调整排期

1. 超管或普通人员进入有权限的项目甘特图页签；
2. 拖住「首页开发」条形右边缘向右拖动 2 格；
3. 预览气泡显示结束时间变化，按天吸附；
4. 松手后保存，左侧结束时间同步更新；
5. 刷新页面后时间保持不变，表示持久化成功。

## 5. 数据模型（概要）

以下为支撑核心权限规则的最小数据模型，字段细节可在技术设计中扩展。

### 5.1 实体关系

```text
User 1---* TeamMember *---1 Team
Team 1---* Group 1---* GroupMember *---1 User
Team 1---* Project 1---* Task *---1 Group
Task *---1 User（负责人）
```

### 5.2 表结构

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| users | id, username(unique), email(unique), password_hash, system_role, created_at | 用户基础信息与平台角色 |
| teams | id, name, description, status, created_by | 团队 |
| team_members | team_id, user_id | 团队成员关系，普通人员可属于多个团队 |
| groups | id, team_id, name, description, status | 小组，team 内名称唯一 |
| group_members | group_id, user_id | 小组多对多关系，实现一人多组 |
| projects | id, team_id, name, description, status, created_by | 项目 |
| tasks | id, project_id, group_id, title, detail, assignee_id, start_at(null), end_at, status, priority, created_by | 任务 |

### 5.3 可见性查询示意

用户在某项目内可见任务的判定：

```sql
SELECT t.*
FROM tasks t
WHERE t.project_id = :projectId
  AND t.group_id IN (
    SELECT gm.group_id
    FROM group_members gm
    JOIN groups g ON g.id = gm.group_id
    WHERE gm.user_id = :userId
      AND g.team_id = :teamId
  );
```

## 6. 非功能需求

1. 安全：密码单向哈希；服务端全量权限校验；防越权、防探测；登录失败限流；
2. 性能：项目内 1000 条任务时列表与甘特图首屏加载不超过 2 秒；甘特拖拽保存响应不超过 500ms；
3. 兼容性：支持主流现代浏览器（Chrome、Edge、Safari、Firefox 最新两个大版本）；
4. 可用性：关键操作（删除、归档）二次确认；保存失败可回滚并重试；
5. 数据：任务软删除；删除项目保留 30 天可恢复窗口。

## 8. 关键验收标准

1. 仅属于 A 组的用户，在任意项目、列表或甘特图中都无法看到 B 组任务；直接访问 B 组任务 URL 返回 404；
2. 同属 A、B 两组的用户能看到两组任务并集，且可按组筛选；
3. 注册时两次密码不一致、邮箱格式错误、用户名重复均有明确提示；
4. 登录密码错误提示「用户名或密码错误」，连续失败触发锁定；
5. 创建任务缺少标题、负责人或结束时间时无法提交；
6. 指定负责人时，下拉列表只出现所选小组成员；
7. 开始时间晚于结束时间时无法保存，甘特图拖拽越界时自动贴合并提示；
8. 甘特图拖拽条形左/右边缘与整体拖动分别正确修改开始时间、结束时间与整体平移，刷新后数据保持；
9. 无开始时间的任务在甘特图按结束时间和当前颗粒度渲染为一个单元格条，不自动生成开始时间；
10. 普通人员可在所属团队创建项目，并可创建、修改和拖拽调整自己可见的任务；超管可执行全部管理操作。
