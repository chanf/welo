## 1. 目标与范围

为任务增加“前置任务”和“后置任务”，让项目成员能够表达任务之间的时间约束，并在甘特图中快速建立、查看、调整依赖关系和批量重排。V1 只处理同一项目内的任务依赖；普通保存不自动移动日期，用户明确点击“重排”后才执行批量调整。

## 2. 核心概念

- **前置任务**：当前任务开始或结束所依赖的任务。例：开发的前置任务是设计。
- **后置任务**：依赖当前任务的任务。例：测试是开发的后置任务。
- **依赖关系**：一条有方向的连接，记录来源任务端点、目标任务端点和约束类型。显示方向为“前置任务 → 当前任务”；后置任务是同一关系的反向展示，不单独创建第二条关系。
- **任务端点**：每个有日期的任务条都提供“开始”和“结束”两个连接点。端点只决定约束类型，不改变任务日期。

### 2.1 四种关系语义

| 类型 | 连接方式 | 产品含义 | 最低约束 |
| --- | --- | --- | --- |
| 开始-开始（SS） | 前置开始 → 当前开始 | 两个任务必须同时开始或当前任务不得早于前置任务开始 | 当前开始 ≥ 前置开始 |
| 开始-结束（SF） | 前置开始 → 当前结束 | 当前任务结束不得早于前置任务开始；适用于交接、替班等场景 | 当前结束 ≥ 前置开始 |
| 结束-开始（FS） | 前置结束 → 当前开始 | 前置任务完成后当前任务才能开始；这是默认、最常用关系 | 当前开始 ≥ 前置结束 |
| 结束-结束（FF） | 前置结束 → 当前结束 | 当前任务不能早于前置任务结束，两个任务都完成后项目阶段才算完成 | 当前结束 ≥ 前置结束 |

“必须同时开始”对应 SS；“两个都完成后才算完成”对应 FF。若用户只在任务详情中选择前置/后置任务而不指定端点，默认创建 FS，并允许在甘特图中改成其他类型。

## 3. 设置入口与操作方法

### 3.1 任务详情/编辑表单

新增两个字段：

1. **前置任务**：可搜索当前项目内可见任务，多选；每行显示任务名称、关系类型和删除按钮。
2. **后置任务**：只读反向列表，展示哪些任务依赖当前任务；可点击进入对应任务。为避免同一关系被维护两次，不在此处直接编辑，新增关系统一从当前任务的“前置任务”或甘特图连线完成。

表单保存时一次提交依赖变更。任务自身不可作为自己的前置任务；已删除、不可见或不属于当前项目的任务不能被选择。

### 3.2 甘特图全屏编辑模式

1. 进入全屏后，任务条默认保持现有视觉；鼠标移入任务条显示左右两个锚点，分别贴近任务条的开始端和结束端。
2. 按住锚点拖动，沿时间轴移动到另一任务的开始端或结束端；目标端点高亮并显示关系类型预览（SS、SF、FS、FF）。
3. 松开鼠标后创建依赖，连线箭头指向后置任务；成功后保留连线，失败则恢复预览并提示原因。
4. 连接已有关系时，拖动任一端点可改绑任务或端点；点击连线后按 `Delete/Backspace`，或使用连线浮层的删除按钮，可解除关系。
5. 非全屏模式只展示依赖连线和冲突提示，不显示锚点，避免影响日常浏览。

### 3.3 视觉与可访问性

- 前置到后置使用单向箭头；四种关系使用不同端点形状或短标签区分，不能只依赖颜色。
- 任务条被遮挡时，连线可从任务条上下方绕行；多条线不得改变任务条高度。
- 锚点、连线和关系类型均提供键盘操作及 `aria-label`；触屏设备使用点击任务后再点击目标端点的两步操作替代悬停拖动。
- 拖动中显示“前置任务 → 后置任务 / 关系类型”，并在产生循环或跨项目连接时即时阻止落点。

### 3.4 任务重排

“重排”按钮仅在甘特图全屏编辑模式显示。用户应先完成依赖和优先级设置，再点击按钮；系统先展示确认摘要（将调整的任务数、受影响的负责人、最早完成时间），确认后生成一次重排预览。

重排算法遵循以下顺序：

1. 先校验权限、任务日期、依赖图和循环关系；存在无法计算的关系时整体不执行。
2. 按依赖拓扑顺序计算任务最早可开始时间，满足 SS、SF、FS、FF 约束，并保持每个任务原有时长。
3. 同一负责人出现时间重叠时，按用户设置的“重排优先级”从高到低安排；优先级相同则按原开始时间，仍相同则按任务创建时间和任务 ID 稳定排序。
4. 被顺延任务继续推动其后置任务，直到所有依赖和负责人占用冲突消除。
5. 生成预览后，用户可以逐项查看原排期、新排期、触发原因（依赖或负责人冲突），选择“应用重排”或“取消”。应用时作为一个批次提交，失败则全部回滚。

优先级是项目内任务的整数排序值，数值越大越优先；可在任务编辑表单、任务列表批量操作和甘特图任务菜单中设置。优先级只用于解决同一负责人之间的无序冲突，不会覆盖依赖约束，也不会改变任务时长或负责人。

## 4. 规则与边界

1. 依赖只能连接同一项目内的两个有效任务，遵循当前用户的任务可见性和编辑权限。
2. 同一对任务同一方向只允许一条关系；反向关系视为重复或循环，禁止创建。
3. 依赖图不得形成环。创建或修改前必须服务端校验，返回可读的环路路径。
4. 任务没有开始时间时，只能作为被依赖任务的逻辑节点，不能连接“开始”端点；补齐日期后才允许完整端点连接。结束时间为空的任务不能连接“结束”端点。
5. 项目归档、任务删除后，相关依赖进入只读/失效状态并保留审计信息；恢复任务时重新计算有效性。
6. 依赖冲突不自动改期。若当前开始早于 FS 前置结束等约束，任务条显示冲突标记，详情中列出违反的关系、日期和建议动作。
7. 拖拽任务日期导致冲突时允许保存，但必须明确提示；点击“重排”才会按依赖和负责人规则批量调整。

## 5. 反馈与异常

- 创建成功：提示“已建立依赖：A → B（结束-开始）”。
- 失败原因：无权限、目标任务不存在、跨项目、重复关系、形成循环、端点无日期、并发版本过期。
- 并发冲突沿用任务编辑的 `409 VERSION_CONFLICT` 处理：撤销本次连线变更、重新拉取项目任务和依赖，再提示用户重试。
- 删除关系需二次确认；删除后可通过撤销提示在当前页面恢复一次。
- 重排完成：提示“已重排 N 个任务”，并提供“查看变更”入口；取消或失败时不改变任何任务日期。
- 重排失败原因：循环依赖、缺少必要日期、无效任务、权限不足、版本冲突或服务端计算超时。

## 6. 数据与接口建议

新增 `task_dependencies` 关系表：`id`、`project_id`、`predecessor_task_id`、`successor_task_id`、`predecessor_endpoint`、`successor_endpoint`、`created_by`、`created_at`、`updated_at`。其中 endpoint 取 `start|end`，并以唯一索引防止重复关系。

甘特图接口返回 `dependencies` 数组和任务的 `reorderPriority`。新增、修改、删除依赖及重排预览/应用使用项目级接口，并携带 `expectedUpdatedAt` 做乐观并发控制。重排应用接口应返回批次 ID、变更前后日期和每条变更原因。所有读写接口执行项目归属、任务可见性、权限和环路校验，前端校验仅用于即时反馈。

## 7. 验收标准

1. 用户可在任务编辑表单添加、查看和移除前置任务，后置列表能同步反映。
2. 全屏甘特图悬停显示锚点，拖动到四类端点均能创建正确类型的依赖。
3. 依赖连线方向、端点和冲突状态在刷新后保持一致；普通浏览模式不出现可误操作的锚点。
4. 系统拒绝自依赖、重复关系、跨项目关系和循环关系，并给出明确提示。
5. 无日期任务、归档项目、删除任务和并发更新均符合本文规则，且不破坏现有甘特图拖拽排期。
6. 同一负责人存在重叠任务时，用户设置的优先级决定排程顺序；优先级相同按规定的稳定规则处理。
7. 点击“重排”可预览并一次性解决依赖冲突和负责人时间重叠；取消、校验失败或并发失败时不产生部分更新。
